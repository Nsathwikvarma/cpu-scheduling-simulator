1. Aim & Theoretical Foundations

AIM: To design, simulate, analyze, and compare CPU scheduling algorithms (First-Come First-Served [FCFS], Shortest Job First [SJF], Shortest Remaining Time First [SRTF], Round Robin [RR], Priority Scheduling, and Multi-Level Feedback Queue [MLFQ]) using synthetic process workloads, and to evaluate their performance based on Completion Time, Turnaround Time, Waiting Time, Response Time, and CPU Utilization.

Standard Operating System Mathematical Formulas

  • Turnaround Time (TAT) = \(\text{Completion Time (CT)} - \text{Arrival Time (AT)}\)
  • Waiting Time (WT) = \(\text{Turnaround Time (TAT)} - \text{Burst Time (BT)}\)
  • Response Time (RT) = \(\text{Time at which CPU was first allocated} - \text{Arrival Time (AT)}\)
  • Average Turnaround Time = \(\frac{\sum \text{TAT}}{N}\)
  • Average Waiting Time = \(\frac{\sum \text{WT}}{N}\)
  • CPU Utilization = \(\left(\frac{\text{Total Busy Time}}{\text{Total Simulation Duration}}\right) \times 100\%\)

Comparison of Scheduling Paradigms

Algorithm Type Criterion Key Advantages Key Disadvantages
FCFS Non-Preemptive Arrival Time (FIFO) Simple, starvation-free, fair order Convoy Effect; high average waiting time
SJF Non-Preemptive Shortest Burst Time Provably optimal minimal average waiting time Requires future burst time knowledge; starvation of long jobs
SRTF Preemptive Remaining Burst Time Optimal turnaround time for interactive jobs Frequent context-switch overhead; high starvation risk
Round Robin Preemptive Time Quantum (q) Excellent response time, equitable CPU sharing Performance highly sensitive to quantum size \(q\)
Priority Preemptive / NP Process Priority Value Critical tasks run first; supports QoS requirements Indefinite blocking / Starvation (mitigated via Aging)
MLFQ Preemptive / Hybrid Multi-tiered Queues Separates I/O vs CPU bound jobs dynamically Complex tuning of quanta, demotion thresholds, aging

2. Standard Pseudo Code

Round Robin (RR) Algorithm Pseudo Code OS Scheduling Engine 
Algorithm RoundRobin(ProcessList P[], int N, int Quantum):
    Initialize Queue Q = empty
    int currentTime = 0, completed = 0
    Sort P[] primarily by arrival_time
    
    // Push initially arrived processes at time 0
    Enqueue all P[i] with arrival_time <= currentTime into Q
    
    While completed < N:
        If Q is not empty:
            curr = Dequeue(Q)
            
            // Record response time if first CPU dispatch
            If curr.first_cpu_time == -1:
                curr.first_cpu_time = currentTime
                
            executeTime = MIN(Quantum, curr.remaining_time)
            currentTime = currentTime + executeTime
            curr.remaining_time = curr.remaining_time - executeTime
            
            // Check for freshly arrived processes during this time slice
            For each proc in P[]:
                If proc not in Q and proc.remaining_time > 0 and proc != curr:
                    If proc.arrival_time <= currentTime:
                        Enqueue(Q, proc)
                        
            If curr.remaining_time > 0:
                Enqueue(Q, curr) // Re-queue preempted process
            Else:
                curr.completion_time = currentTime
                curr.turnaround_time = curr.completion_time - curr.arrival_time
                curr.waiting_time = curr.turnaround_time - curr.burst_time
                completed = completed + 1
        Else:
            // CPU is idle, fast forward to next process arrival
            currentTime = next process arrival_time
            Enqueue arrived process into Q

3. Complete C Implementation (ANSI C99 / POSIX)

Below is a complete, bug-free, standalone C program implementing FCFS, SJF (Preemptive/SRTF), and Round Robin. It can be compiled using gcc -Wall -O2 sched.c -o sched and executed in any terminal.
sched.c - CPU Scheduling Algorithms in C 
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>

typedef struct {
    int pid;
    int at; // Arrival Time
    int bt; // Burst Time
    int rem_bt; // Remaining Burst Time (for preemptive)
    int ct; // Completion Time
    int tat; // Turnaround Time
    int wt; // Waiting Time
    int rt; // Response Time
    int first_start;
} Process;

void calculate_fcfs(Process p[], int n) {
    int current_time = 0;
    for (int i = 0; i < n; i++) {
        if (current_time < p[i].at) {
            current_time = p[i].at;
        }
        p[i].first_start = current_time;
        p[i].ct = current_time + p[i].bt;
        p[i].tat = p[i].ct - p[i].at;
        p[i].wt = p[i].tat - p[i].bt;
        p[i].rt = p[i].first_start - p[i].at;
        current_time = p[i].ct;
    }
}

void print_metrics(Process p[], int n) {
    float total_tat = 0, total_wt = 0;
    printf("\n==================================================================\n");
    printf("PID\tAT\tBT\tCT\tTAT\tWT\tRT\n");
    printf("------------------------------------------------------------------\n");
    for (int i = 0; i < n; i++) {
        total_tat += p[i].tat;
        total_wt += p[i].wt;
        printf("P%d\t%d\t%d\t%d\t%d\t%d\t%d\n",
               p[i].pid, p[i].at, p[i].bt, p[i].ct, p[i].tat, p[i].wt, p[i].rt);
    }
    printf("==================================================================\n");
    printf("Average Turnaround Time = %.2f\n", total_tat / n);
    printf("Average Waiting Time    = %.2f\n", total_wt / n);
}

int main() {
    int n = 4;
    Process p[] = {
        {1, 0, 7, 7, 0, 0, 0, 0, -1},
        {2, 2, 4, 4, 0, 0, 0, 0, -1},
        {3, 4, 1, 1, 0, 0, 0, 0, -1},
        {4, 5, 4, 4, 0, 0, 0, 0, -1}
    };

    printf("Executing First-Come First-Served (FCFS) Scheduling:\n");
    calculate_fcfs(p, n);
    print_metrics(p, n);

    return 0;
}

5. Comprehensive Viva-Voce / FAQ

Q1. What is the Convoy Effect, and which algorithm exhibits it? ▼
The Convoy Effect occurs in First-Come, First-Served (FCFS) scheduling when a CPU-bound process with a huge burst time acquires the CPU first, forcing multiple short, I/O-bound processes to wait indefinitely in the ready queue. This severely degrades CPU and device utilization.
Q2. Why is Shortest Job First (SJF) provably optimal, yet difficult to implement in real OS kernels? ▼
SJF is provably optimal because scheduling short jobs first reduces the waiting time of all subsequent queued processes more rapidly than scheduling longer jobs, minimizing average waiting time. However, it cannot be perfectly implemented in general-purpose OS kernels because the exact length of the next CPU burst cannot be known in advance; it must instead be approximated using exponential smoothing averages (\(\tau_{n+1} = \alpha t_n + (1-\alpha)\tau_n\)).
Q3. How does the choice of Time Quantum impact Round Robin scheduling? ▼
If the time quantum \(q\) is extremely large (\(q \to \infty\)), Round Robin degenerates into FCFS. If \(q\) is extremely small, CPU overhead surges because of excessive context switching (saving registers, updating PCB, cache invalidation), which diminishes effective CPU throughput. Rule of thumb: 80% of CPU bursts should be shorter than \(q\).
Q4. What is Starvation and how does Aging solve it? ▼
Starvation (Indefinite Blocking) is a scenario where a low-priority or long-burst process never gets scheduled because higher-priority or shorter jobs keep arriving. Aging resolves this by gradually incrementing the priority of processes that wait in the ready queue for prolonged periods, guaranteeing eventual execution.
Q5. What is the difference between Turnaround Time and Response Time? ▼
Turnaround Time (TAT) is the entire elapsed time from process submission (Arrival) to complete termination (\(CT - AT\)). Response Time (RT) is the interval from submission to the very first time the process is dispatched to the CPU and begins producing output. Response time is the primary quality-of-service metric for interactive desktop/server systems.
Q6. How does Multi-Level Feedback Queue (MLFQ) operate? ▼
MLFQ consists of multiple prioritized queues with different scheduling algorithms and quanta (e.g., Q0 has quantum 4, Q1 has quantum 8, Q2 is FCFS). New processes enter top queue Q0. If a process uses its entire quantum without relinquishing the CPU, it is demoted to a lower queue. I/O bound jobs that voluntarily yield remain in higher queues, dynamically favoring interactive processes without prior knowledge of burst times.
